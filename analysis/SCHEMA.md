## finance/invoices.csv
`invoice_id str, customer_id str, customer_name str, type cat, issue_date date, due_date date, service_period_months int, amount float(2dp), currency str, status cat, paid_date date|blank, payment_method cat`
Example: `INV-20001, C1194, Stanhope Engineering, subscription, 2022-01-03, 2022-02-02, 12, 5400.00, USD, paid, 2022-02-03, check`
- type: subscription 5,938 / implementation 124
- status: paid 5,801 / written_off 144 / open 63 / overdue 38 / payment_failed 16
- payment_method: card 3,402 / ach 1,789 / wire 681 / check 190
- service_period_months: 1 (3,784) / 3 (1,188) / 12 (1,090); currency all USD
- Traps: `paid_date` is ALSO filled for `written_off` rows (it is the write-off date, always issue+150d). Card invoices have due_date = issue_date (3,384 of 3,402); bank methods are issue+30. All amounts are whole dollars (0 rows with cents). History starts 2022 (contract terms in force at 1 Jan 2023). `paid_date` = date cash was *applied* in the ledger, not received.

| contracts -> customers | customer_id | 0 missing |

Bottom line for the builder: id joins are clean everywhere. The only fuzzy join is bank-receipt payer_name/memo to customer/invoice (the cash-application problem itself) and ticket text to invoice (disputes).
